ADMINISTRATION · INTÉGRATION DES SERVICES

Guide d’intégration

Ajouter une fiche, raccorder les signaux et vérifier les données avant de créer un tableau Grafana.

À retenir

Créer une fiche dans le portail n’installe pas automatiquement une sonde ou un agent. Chaque signal doit être réellement fourni par l’application, son exporter ou une sonde, puis vérifié dans Prometheus.

01 · PORTAIL

Ajouter une application ou un site

  1. Dans Applications, choisir Ajouter une application.
  2. Renseigner le nom, le responsable, le langage, la version et les dates du projet.
  3. Choisir un nom de service unique et stable. Il doit correspondre à OTEL_SERVICE_NAME ou au label service_name des métriques.
  4. Pour un site, ajouter son adresse http:// ou https:// dans Site web. Le dépôt Git est un champ séparé.

La fiche documente le service et ses liens; elle ne déploie pas l’application et ne crée pas, à elle seule, de données de supervision.

02 · OPENTELEMETRY

Instrumenter une application

Ajouter le SDK ou l’auto-instrumentation compatible avec son langage/framework, puis configurer son export OTLP. Pour un conteneur sur le réseau Docker telemetry partagé :

OTEL_SERVICE_NAME=mon-service
OTEL_RESOURCE_ATTRIBUTES=service.namespace=mon-projet,deployment.environment.name=production
OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318
OTEL_EXPORTER_OTLP_PROTOCOL=http/protobuf
OTEL_METRICS_EXPORTER=otlp
OTEL_TRACES_EXPORTER=otlp

Un programme installé sur le même serveur que Docker peut utiliser http://127.0.0.1:4318. Pour Python/FastAPI, installer les paquets opentelemetry-distro et opentelemetry-exporter-otlp, puis démarrer l’application via opentelemetry-instrument. Les mesures métier (files, traitements, erreurs métier) demandent une instrumentation dans le code.

Pour plusieurs réplicas, conserver le même nom de service et identifier chaque instance séparément. Éviter les URL brutes, identifiants utilisateurs, courriels et secrets dans les attributs.

03 · AUTRES SOURCES

Raccorder les exporters et instances

  • Endpoint Prometheus : si l’application expose déjà /metrics, ajouter une cible dans prometheus.yml, avec une adresse joignable depuis Prometheus et un label service_name.
  • Site sans accès au code : ajouter son URL comme cible Blackbox. Cela mesure surtout disponibilité, latence, DNS et réponse HTTP, pas les métriques internes de l’application.
  • Serveur Linux : installer Node Exporter sur chaque hôte à superviser et ajouter sa cible à Prometheus. Node Exporter mesure l’hôte, pas les fonctions métier.
  • Conteneurs Docker : cAdvisor collecte les ressources des conteneurs visibles par son hôte; les métriques de la pile locale sont déjà raccordées.
  • Jenkins ou autre produit : activer son endpoint/exporter officiel, vérifier ses accès, puis le déclarer comme cible Prometheus.

Si l’application est sur un autre serveur, utiliser un réseau privé/VPN, TLS et un pare-feu limité aux hôtes attendus. Le Collector actuel n’est pas publié pour un accès distant direct; ne pas exposer OTLP sans protection.

04 · VALIDATION

Vérifier les données puis créer le tableau

  1. Vérifier que l’application, le Collector et Prometheus sont actifs, puis générer du trafic de test.
  2. Dans Grafana Explore avec Prometheus, exécuter une requête sur le nom de service. Exemple : stagiaires_app_requests_total{service_name="mon-service"}.
  3. Pour un exporter Prometheus, vérifier up{job="mon-exporter"}; pour une sonde, vérifier probe_success.
  4. Confirmer que les valeurs sont réelles et évoluent avant d’ajouter des panneaux. Créer le tableau uniquement avec les métriques présentes.

Les métriques reçues par OpenTelemetry sont exposées à Prometheus par otel-collector:8889; les traces vont vers Tempo et les journaux OTLP vers Loki lorsque l’application les exporte.
